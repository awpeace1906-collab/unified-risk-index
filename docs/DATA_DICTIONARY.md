# Data dictionary: Phase 1 EHR extraction

Generated by `python -m uri.datadict` from the engine's mappings; do not edit by hand.
This is the specification for the retrospective export the Phase 1 derivation replays
(`python -m uri replay export.ndjson --log snapshots.jsonl --outcomes-out outcomes.csv`).

## Request

* **Population:** consecutive adult (>= 18 y) ED encounters over the study period, including
  those discharged from the ED (the composite outcome is only possible after admission, but
  denominators need every encounter).
* **Format:** FHIR R4 Bulk Data export (NDJSON), one file per resource type, or an equivalent
  flat extract carrying the same codes and timestamps.
* **Resources:** `Patient`, `Encounter`, `Observation` (vital-signs and laboratory),
  `Condition` (problem list and encounter diagnoses), `MedicationRequest`,
  `MedicationStatement`, `MedicationAdministration`, `Procedure`, `Consent`.
* **Window:** from 365 days before each ED arrival for creatinine, hemoglobin, platelets,
  bilirubin and pCO2 (pre-episode baselines), 90 days for encounters and procedures (recent
  hospitalization / surgery), to 48 h after arrival (outcomes).
* **Units of analysis:** one ED encounter per subject id. A patient with several ED
  encounters in the period should appear once per encounter (e.g. `patientid-encounterid`),
  because outcomes and calibration rows are taken from each subject's latest episode.
* **Timestamps:** observation/effective times, not result-filed times, wherever both exist.
* **De-identification:** shift dates consistently per patient if required; intervals are all
  the engine needs.

## Outcome definitions (study protocol)

Composite decompensation = first of unplanned ICU transfer, RRT activation, emergent
intubation, vasopressor initiation, in-hospital death, counted at 6 / 12 / 24 / 36 / 48 h
from triage. Planned ICU admissions need a site rule (ED disposition order or chart review)
to be excluded.
